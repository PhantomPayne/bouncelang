### E. Patterns That Worked Well

1. **Union types with atoms** — `:pending | :processing | :complete | :cancelled` read as naturally as an English description. Exhaustive `match` prevents accidents.
2. **Error grouping** — `error ApiError = | NetworkError { ... } | TimeoutError { ... }` composes perfectly with `try` blocks. Adding a new error to a group requires no call-site changes.
3. **Pipeline `|>` with lazy Sequence operators** — The finiteness tag system (`& :finite` / `& :infinite`) is elegant and makes a class of bugs (calling `collect` on an infinite sequence) into compile errors.
4. **Effect propagation without annotations** — Writing `fn process(...)` that calls effectful helpers without any annotation tax was genuinely comfortable. The LSP inlay-hint model offsets the invisibility of effects.
5. **`view` declarations** — Whitelist-only field selection with no blacklist. Adding a field to a `type` never silently changes output. This is an excellent safety default.
6. **`try`/`error` control flow** — No `?` operator, no `catch` keyword, no `Result` wrapper. The `try` block with exhaustive error arms feels like a natural extension of `match`.
7. **World composition with `extends`** — `world server extends base { ... }` with handler override is clean. The test world pattern is immediately obvious.
8. **Opaque types with factory functions** — The design decision that opaque types can only be constructed through factory functions is the right default. Invariants are easy to enforce.
